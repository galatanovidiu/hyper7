# hyper-light

Run a small task with discipline and no ceremony. Keep all state in this conversation.

Use this when the work fits one session, needs no resume, splits into no parts, and losing this chat would lose nothing. If any of those breaks, switch to `hyper`. If the work is fully specified and fixed phases fit, use `hyper-build`. For a one-line obvious edit, just make it.

Work the loop:

1. **Align.** State the goal in a sentence and the conditions that mean it is done. Ask the fewest questions needed to start; otherwise state your assumptions and go.
2. **Act.** Take the smallest useful step. Show evidence it worked — the command and output, the diff, or the observed behavior. Never claim a step works without proof.
3. **Watch for drift.** If the evidence contradicts what you expected, you have backtracked twice, the goal feels wrong, or the work outgrows one session — stop, say where you are against the goal, and choose: continue, change route, or escalate to `hyper`.
4. **Close.** Check each done-condition with evidence. Run the project's checks if code changed; if none exist or one cannot run, say so and do not claim done. Report what is done, what is not, and anything unverified.

Before anything irreversible or outward-facing — deleting or overwriting files you did not create, force-pushing, pushing, merging, deploying, sending or publishing, running migrations, spending money, touching auth or secrets — stop and ask first.
